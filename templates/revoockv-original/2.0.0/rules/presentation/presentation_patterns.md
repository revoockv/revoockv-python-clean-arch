# Presentation patterns (framework-agnostic)

The presentation layer is **delivery mechanism + DI wiring**. Domain and data never change
when you add or swap an adapter. Each adapter lives in its own folder under
`features/<feature>/presentation/`; `presentation/di/` is always there.

## The adapter contract (every adapter, every framework)

1. Parse / validate input into primitives or a presentation schema.
2. Get the use case from its getter: `use_case = sign_in_use_case()`.
3. Call it: `result = await use_case(...)`.
4. `match` the `Result` and map it to the adapter's output; a failure's text comes from
   `<Feature>FailureText.of(failure)` (`presentation/text/`), its HTTP status from `FailureStatus.of(failure.kind)`.

Adapters must NOT:

- import `data/*`, `domain/repositories`, `domain/use_cases` or the container;
- contain business rules (validation beyond input shape, policies, calculations);
- catch exceptions to decide business outcomes — failures arrive as `Failure`;
- hold mutable module state besides the router / command group object;
- use magic strings/numbers inside handler bodies — use `http.HTTPStatus` and constants classes.

Module-level adapter objects (`router = APIRouter(prefix="/auth", tags=["auth"])`,
`commands = typer.Typer(help="...")`) and decorator arguments (`@router.post("/sign-in")`) are
configuration and may use literals.

## FastAPI (`presentation/api/`)

Setup: `init_project.py --adapter fastapi`, then `uv add fastapi uvicorn` and `uv add --dev httpx2`.
Each feature: `init_feature.py --feature <f> --adapter fastapi` creates
`presentation/api/<f>_router.py` + `schemas/` and includes the router in `main.py`.

```python
router = APIRouter(prefix="/songs", tags=["songs"])


@router.post("", status_code=HTTPStatus.CREATED)
async def add_song(body: AddSongRequest) -> SongResponse:
    """Add a song; 422 when the title is empty."""
    use_case = add_song_use_case()
    match await use_case(title=body.title, author=body.author):
        case Success(song):
            return SongResponse.from_entity(song)
        case Failure(failure):
            raise HTTPException(
                status_code=FailureStatus.of(failure.kind), detail=SongFailureText.of(failure)
            )
```

- Request/response models are Pydantic `BaseModel`s in `presentation/api/schemas/`, one per file
  (`add_song_request.py`, `song_response.py`). Responses map from entities with `from_entity`.
- Do not use `Depends(...)` to inject use cases — that requires importing use case types into the
  router. Call the getter inside the handler. `Depends` is fine for request-scoped HTTP concerns
  (auth headers, pagination params).
- The status of a failure is `FailureStatus.of(failure.kind)` (core, the same for every router); a router that
  answers several failures puts the `HTTPException` in one `_http_error(failure)` helper. No HTTP codes in domain.
- App assembly and lifespan live in `main.py` (`create_app()`), generated by `init_project.py`.
- Run: `uv run uvicorn <package>.main:app --reload`.

## Typer CLI (`presentation/cli/`)

Setup: `init_project.py --adapter typer`, then `uv add typer`. Each feature:
`init_feature.py --feature <f> --adapter typer` creates `presentation/cli/<f>_commands.py`
and mounts it in `main.py` with `app.add_typer(<f>_commands, name="<f>")`.

```python
commands = typer.Typer(help="Song commands.", no_args_is_help=True)


class SongCommandsText:
    """User-facing CLI text of the song commands."""

    ADDED = "Added {title} by {author}"


@commands.command("add")
def add(
    title: Annotated[str, typer.Option(help="Song title.")],
    author: Annotated[str, typer.Option(help="Song author.")],
) -> None:
    """Add a song; exits with code 1 on failure."""
    use_case = add_song_use_case()
    match asyncio.run(use_case(title=title, author=author)):
        case Success(song):
            typer.echo(SongCommandsText.ADDED.format(title=song.title, author=song.author))
        case Failure(failure):
            typer.echo(SongFailureText.of(failure), err=True)
            raise typer.Exit(code=1)
```

- Output via `typer.echo` (or `rich`), never `print`.
- `main.py`'s `@app.callback()` runs `register_and_init()` before any command.
- Run: `uv run <project-name> <feature> <command>` (script entry point is added by `init_project.py`).

## Other adapters (worker, bot, gRPC, scheduler, plain script)

Create `presentation/<adapter>/` and follow the same contract: entry function → getter → use case
→ `match` → output. Start-up goes through `register_and_init()` in the adapter's entry point in
`main.py` (or a second root module such as `worker.py`).

## Several adapters in one project

Allowed and common (API + CLI for admin tasks). Each feature gets `presentation/api/` and
`presentation/cli/` side by side; both call the same getters. Add a second root entry module
(`cli.py` next to `main.py`) for the second adapter and point `[project.scripts]` at it.
